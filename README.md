# home

> 以「人」为索引的私人关系数据库与 AI 助理 —— [marsdata.ai](https://marsdata.ai)（Mars Agent）的本地自托管复刻版。

## 这是什么产品

home 是一个**完全跑在你自己机器上**的「关系维护 Agent」。它不是日历、不是待办清单、也不是传统 CRM——它按**人**而不是按时间/主题组织信息：

你平时在聊天、截图、文件、网页里遇到的关于「你在乎的人」的一切（换了工作、孩子上几年级、答应过什么、随了多少份子钱、上次聊到什么时候），都被自动抽取成**结构化档案**，挂上时间线，并能在你需要时回答问题、到期提醒、代拟消息。

一句话：**替你的记忆打工，把人情往来变成可查询、可回溯、可执行的数据。**

与云端 Mars Agent 的本质区别：所有数据（SQLite + blob）都在本地，LLM 调用走你自己的 API key，随时可以导出或彻底删除。

## 主要做什么

### 1. 自动建档（输入 → 结构化档案）
- **对话直说**：聊天中随口一提「王工刚升了技术总监」，自动抽取成字段，进入人物档案。
- **截图识别**：发微信聊天截图，vision 模型转写后走同一抽取管线。
- **文档/网页**：导入文件或粘贴 URL，抓取正文后抽取。
- **批量导入**：CSV / vCard 联系人一键导入。
- **聊天记录导入**：微信/QQ 导出的 .txt 记录，容错解析 5 种常见格式 → 按「对方 × 日期」切块 →
  抽取时把对方名字写进片段表头，保证事实归属正确；「我」是谁自动判断（不确定会明说）。

### 2. 身份消歧（绝不认错人）
同名「老王」到底是不是同一个人？四路召回 + 加权打分 + 三档决策：
- **≥0.85 且领先差值 ≥0.10** → 直接归并；
- **0.50–0.85** → 进待确认队列，问你；
- **<0.50** → 建新人物。
即使分数高、但两个候选分差不够，也**必须回问**，绝不静默合并。

### 3. 双时态记忆（时间是一等公民）
每条字段带 `valid_from`（事实何时成立）、`valid_to`、`recorded_at`（系统何时录入）。支持「2024 年的时候他做什么工作？」这类**历史回溯查询**，而不是只保留最新值。

### 4. 五层记忆
语义（属性字段）、情景（事件）、反思（周结）、日志（每日 journal）、技能（沉淀下来的话术/流程）——五层各有独立写入路径和检索策略。

### 5. 问答与代笔（代笔不代发）
- 「老王们最近谁有变动？」「我答应过孩子什么？」——混合检索（SQL + FTS5 分词 + 向量余弦 + 时间衰减）给出带来源的答案。
- 可以帮你**起草**祝福语/开场白，但**绝不替你发送**。

### 6. 承诺与提醒
「下周五前给张总方案」自动建承诺 + 定时提醒（APScheduler，每分钟轮询，本地时区 Asia/Shanghai）。

### 7. 人情账本
随礼、借贷按人记账；待确认条目不进入任何汇总，杜绝「没确认的钱也算了总数」。

### 8. 待确认队列
所有不确定的抽取结果进 Pending 面板，人工确认/丢弃后才生效——假设优于断言，但不等于断言。

### 9. 合并与拆分
误建的两个「老陆」可合并，合并时写快照（tombstone），可**反向拆分**恢复原状；删除分两级——**归档**（从列表/检索消失、可恢复）与**彻底清除**（物理删，含别名/字段/记忆/账本/提醒/关系边/向量索引/独占 blob）。两者都不是「假装删掉」：清除完会逐表自检，有残留就报「部分删除」。

### 10. Deep Research
需要深度调研时：预检索 → 出研究提案 → 3 个边界互斥的子 Agent 并行调研 → lead agent 审校（丢弃无来源的论断）→ 出带引用来源的报告。

## 产品原则（七条不变量，写进代码而非口号）

| # | 原则 | 代码体现 |
|---|------|---------|
| P1 | 永不静默合并 | `disambiguate.py` 三档决策 + 分差门槛 |
| P2 | 写入必有回执 | 全部 16 个工具返回结构化 receipt |
| P3 | 时间是一等公民 | 双时态字段 + 间隔感知 + 全本地时区 |
| P4 | 假设优于断言 | 抽取带 confidence + evidence，低置信进 pending |
| P5 | 删除是真删除 | **两级语义已实现**：`DELETE /api/persons/{id}` 归档（打 `deleted_at`，从列表/检索消失、可恢复）+ `POST /api/persons/{id}/purge` 彻底清除（物理删，含别名/字段/记忆/账本/提醒/互动/关系边/向量索引/该人独占的凭证与 blob）。删完 `repo.verify_purged()` 逐表自检，有残留即报「部分删除」而非「已删除」（FR-ID-02） |
| P6 | 代笔不代发 | 系统提示硬约束 + 无发送类工具 |
| P7 | 不假装知道 | 「严禁模拟工具」硬规则；无来源论断被审校丢弃 |

沙箱环境下 pytest 默认 tmp 目录会报 `PermissionError: EEXIST`，需显式 `--basetemp` 指到项目内
（`.pytest-tmp/` 已在 `.gitignore`）。

⚠️ 评测的 `--no-cache` 不是可选项：缓存存的是 **sanitize 之后**的结果，而缓存键只含提示词 hash。

## 设计取舍备忘（踩过的坑）

- `person_alias` 主键是 `(person_id, alias, source)` 而非 `(alias, source)`——后者会让共用别名的第二个人被静默丢弃。
- 别名精确命中基线给 0.9，否则永远到不了绑定阈值。
- `upsert_field` 同毫秒两写会撞 `valid_from` 主键，冲突时 +1ms。
- 模型可能「角色扮演」调用工具（输出"正在调用天眼查API"），系统提示里必须有「严禁模拟工具」硬约束。
- DuckDuckGo 在代理下 502，网页检索走 Bing；其真实 DOM 结构是 `<h2 ...><a target=_blank href=...>`，正则要宽松。
- 「客套不算承诺」不能只写进提示词：实测模型仍会低置信地猜出「以后常见面」（0.4 分），
  指标上从「误写」降成「待确认」，问题并没消失。改由 `extract.py:_is_pleasantry()` 在代码里拦掉，
  并用 `_CONCRETE`（把…给…/周X/号/数词+量词）反向豁免，避免误杀「下次见面把合同签了」这类真承诺。
- **客套闸门不能用动词白名单**。曾用「触发词 + 动词表（吃饭|聚|聊|见面…）」判定，结果「回头再说吧」「改天请你搓一顿」照漏——
  白名单把「枚举动词」当成了必要条件，是**错的抽象**。改成反向判定：**命中客套触发词 且 全句无具体动作/时间 → 客套**。
  另外，闸门要同时判 `content` 与 `evidence`：`content` 是模型自由发挥的字段（会把「回头我加你微信」改写成「加你微信」从而躲过闸门），
  `evidence` 才是被强制成原文连续片段的字段。
- **角色词/亲属称谓不是人**（FR-ID-01），但闸门只拦 `people[]` 不够：`apply.py` 的 relations 分支在
  `get_person_by_name(to)` 落空时会 `create_person(to)`，于是「前台」会从关系这条路过闸变成档案。
  所以闸门要**下沉到落库层**（最后一道闸门）。同时**不做**「没有明确参照人就塞给本批唯一那个人」的兜底——
  那是 FR-MEM-06 禁止的「把他人特征归档到当前人物名下」；只有指名道姓的 `X的<亲属>` 才做归属，且家属信息要收拢到本人、用原文逐字片段。
- evidence 与 confidence 是**正交**的两个信号：`sanitize()` 只清理**伪造的凭证**（不在原文里就清空），
  **不顺手改置信度**——偷偷调分会掩盖模型自身的校准误差，让 confidence 这个指标失去意义。
- 往提示词加约束要同时给「正向配重」：只加否定式规则（不算/不是/不要）会让模型过度收敛，
  把该记的事一起减掉（`extract-r07` 的 `facts` 曾被整条清空），而这类回归**不会触发任何门槛告警**。
- 相对日期（「这周五」「下周五」「下个月5号」）**不能让模型自己算**：LLM 的星期/月份运算不可靠。
  要把「今天是 2026-09-30（周三）」连同「本周/下周以哪天为界」「本月/下个月是哪个月」一起喂进去，
  否则提醒会建在错的日子上（FR-TIM-02）。而且**给一部分权威值会把剩余的推算锚歪**——
  只给周界没给月界时，周界里全是 10 月日期，模型实测把「下个月 5 号」锚成了 11-05。
