## 实际验证结果

- 两轮各 36 条样本真实调用配置的抽取模型，共 72 次；第一轮精确字段匹配 81/82，修复后第二轮 82/82。第二轮没有遗漏或意外生成预期承诺、账目，两条同名身份样本均进入待确认。角色词、纯查询和起草指令未新增人物或事实。同来源重放未增加数据。
- 最终体验库使用第二轮保存的模型输出，在修复后的写入逻辑上重新建库并重放。这次建库没有重新采样模型，原报告在 `mock-20261001-221103/report.json`，最终重放报告在当前目录的 `report.json`。
- 3 个真实对话任务、2 张模拟图片的视觉识别、1 份群聊导入全部完成。对话请求的重复提交复用同一任务；群聊文件再次上传返回重复回执，共产生 7 条任务记录。
- 47.23 元餐费只记一笔支出，验收文件承诺只保存一条；68.42 元收款方向与金额正确。名片和群聊中三个人的 9 个预期公司、职位、城市字段全部匹配，名片生日也保存成功。每个对话只保留一条用户消息和一条最终回答。具体断言在当前目录 `e2e.json`，8 项检查全部通过。
- 首页、人物、待确认、账本、承诺、项目、星图共 140 次 HTTP 读取，8 个并发线程，零失败。本机该次测量中位数 115.09 ms、P95 236.01 ms；包含 HTTP 与调度开销，并且与自动测试同时运行，不能作为部署性能承诺。
- 浏览器验证公司信息能区分同名人物；账本能从第 1–100 条翻到第 101–114 条；61 位人物的星图默认平面显示，点击节点可打开档案。林舟 2024 年的合肥历史保留，当前杭州未被覆盖。390×844 窄屏同名卡片正常显示，观察到的浏览器错误日志为空。
- 当前全套自动测试 **209 项通过**，前端语法、Python 编译与差异空白检查通过。

这轮发现并修复了起草要求被记成个人事实、历史城市只落成普通记忆、同一句转账在工具和抽取入口方向冲突、带日期前缀的承诺重复、同名候选缺乏区分信息、账本超过 100 条无法查看、星图内圈拥挤的问题。收支方向校验只纠正原文明确写出人物、方向和同一金额的矛盾；复杂表述仍使用模型与待确认流程。

## 复现

只生成批量数据，不调用模型：

```powershell
.venv/Scripts/python.exe -m scripts.mock_scenarios
```

生成新库并实际调用网关抽取上述 36 条样本：

```powershell
.venv/Scripts/python.exe -m scripts.mock_scenarios --live
```

已有完整抽取结果时，可以不再调用模型，重放到另一个新库：

```powershell
.venv/Scripts/python.exe -m scripts.mock_replay
```

生成脚本限制输出在 `data/qa/`，拒绝覆盖已有数据库。生成新库后，停止旧的 8767 服务，在独立的 PowerShell 终端启动新库：

```powershell
$mockRun = (Get-Content data/qa/latest-mock.json -Raw | ConvertFrom-Json).run_dir
$env:HOME_DB_PATH = Join-Path $mockRun 'home.db'
$env:HOME_BLOB_DIR = Join-Path $mockRun 'blobs'
.venv/Scripts/python.exe -m uvicorn app.api.main:app --host 127.0.0.1 --port 8767
```

另一个终端运行完整链路验收（需要模型连接，要求新库还没有任务）：

```powershell
.venv/Scripts/python.exe -m scripts.mock_e2e
```

验收脚本先核对服务人物 ID 与新库一致，防止对旧库误测；结果保存到库所在目录。正式工作台仍使用另一个终端的 `run.ps1` 和默认端口 8000。
