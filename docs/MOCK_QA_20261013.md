## macOS 复现

使用安装了 `requirements.txt` 的 Python 3.12 环境，例如：

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

生成独立测试库，实际调用已配置的模型：

```sh
.venv/bin/python -m scripts.mock_scenarios --live
```

已有完整抽取输出时，重新建库可使用 `.venv/bin/python -m scripts.mock_replay`。两个脚本都限制输出在 `data/qa/`；重新生成后，需停止旧的模拟服务再切换数据库。

启动新库（单独终端）：

```sh
MOCK_RUN="$(.venv/bin/python -c 'import json; from pathlib import Path; print(json.loads(Path("data/qa/latest-mock.json").read_text())["run_dir"])')"
HOME_DB_PATH="$MOCK_RUN/home.db" HOME_BLOB_DIR="$MOCK_RUN/blobs" \
  .venv/bin/python -m uvicorn app.api.main:app --host 127.0.0.1 --port 8767
```

另一个终端执行 `.venv/bin/python -m scripts.mock_e2e`。完整链路脚本要求最新库尚无任务，重复验收前需要先重建库。脚本运行结束后应检查 `e2e.json` 的 `failed_checks` 和任务状态；当前脚本不会仅因语义断言失败返回非零退出码。
