# 0.14 记忆写入与沟通草稿验收

## 本轮实现

版本为 0.14.0。本轮集中改善同名人物写入、称呼与事实的区分，以及沟通草稿实际交付正文的行为，沿用 0.13 的来源投影、只读恢复和独立回执。

### 人物与事实的写入约束

`app/memory/write_grounding.py` 提供抽取应用与写工具共用的窄约束：

- 按每条 patch 的原始称呼匹配已选人物，优先最长完整别名，不把同一批次全部信息强绑给一个人。模型自行生成的规范名不能把新称呼静默指向已有身份；这种情况进入身份待确认。
- 对单人代词只接受封闭的主语或用户转账表述；代词不加入人物别名。「何晴说她……」不能继承此前选择的另一人物。
- 对已选人物，在调用分类模型前冻结原文别名的归属；抽取应用和所有写工具入口重新检查人物可用状态及别名 owner。等待期间删除、转移或增加同名归属会拒绝写入。读取工具继续接收原读取范围。
- 旧记事重试绑定原消息的人物范围；后续选择另一人物不改变旧任务对象，原称呼归属已经改变则拒绝重放，保留原消息元数据。
- 称呼中的修饰词不能单独支持 company、city、事实或价值判断。原文明示的工作、城市和职位仍可保存。不可信规范名不参与原文掩码，避免抹掉真实事实。
- 对「在……工作」中模型只抽出单位前缀的情况，不扩写公司名，保留模型原候选并降低到待确认；只出现在该单位片段内、没有独立任职依据的 title 不保存。显式「担任／做／从事／任」职位保留。

被绑定、跳过或转为待确认的候选记录在 `write_audit` 中；抽取结果随原用户消息保存，工具结果随工具轨迹保存。生成失败和实际保存结果继续分别展示。未新增数据库迁移，不改用户已有资料。

这些规则不是通用语义验证器。它们不能保证所有新人物、复杂代词、否定句、公司边界和模型生成字段都正确；没有触发规则的高置信抽取仍沿用既有写入策略。完整机构名是否被模型正确抽取仍需实测。

### 沟通正文与待补信息

普通聊天、一次结构化资料编辑和持久沟通准备共用草稿要求：实际输出所需渠道正文，未知数量、交期、规格与材料用明确占位；发送前整理、确认、添加附件的动作另列，保留「先……确认后再……」的条件。不把未完成承诺写成已整理、已附上或已发送。

展示契约增加 `draft_requested`，明确代笔若只返回资料、建议或 no_answer，会以 `requested_draft_missing` 拒绝作为完成结果，并提示重试回答。缺少原文等必要输入时可保留具体澄清问题，记为 `needs_input`。纯资料查询仍使用服务端资料投影与固定澄清提示；展示许可不授予写权限。

`generation_task` 仅核对段落形状，`method=segment_shape_only`、`semantic_verified=false`。有 draft 段落不证明字数、语气、条件和附件表述全对；后文逐步审阅与机器检查分别报告。

首次失败后的补修增加「起封邮件」「改成两句话」等口语命令识别，以及受控的前文编辑承接：只有紧邻的最终助手消息已完成服务端资料审阅、确有 draft 段，且与前一用户消息的单人物范围一致，闭合的精简、长度、翻译或语气编辑才重新读取该人物。明确人物、全库和需澄清范围优先；在识别到的编辑请求中，粘贴新稿或含未知姓名的语句不通过这一承接规则；识别仍采用闭合语言启发式。缺少上述草稿标记的旧回答需明确对象。编辑读取范围不授予新记忆写权限。

## 验收方法与冻结边界

本轮验证两类问题：记忆是否以正确值落入正确人物，以及草稿是否实际完成起草、改稿和发送前准备要求。它们分别检查；来源编号有效、回答非空或分类标签正确，均不能代替上述结果。

语料为内部虚构开发构造，不是现实联系人、外部盲测或真实用户分布。`known_regression` 沿用 0.13 已暴露的反例；`new_wording` 由独立验收代理在实现冻结前构造并冻结，具体问句与预期不向实现代理披露，待实现冻结后才采样。后者仍与本轮已知问题类型同源，不能称独立外部泛化基准。第一次采样之后，两组都属于已知开发语料；后续修复重跑必须标为回归并保留首次结果。

固定语料为 `eval/fixtures/write_quality_v014.json`，共 9 个场景、18 个步骤：已知回归 6 场景 12 步，新措辞 3 场景 6 步。冻结值为：

- 规范化 JSON SHA256：`868eb486b76775807c0ca60a85dd1080e10b5a309aa8f534390b75e8d3de99f1`。
- 文件 SHA256：`c36b55e7337dbce9d88e49ad1910c890a1cd015d8099ec3de64645467f65e498`。

| 范围 | 固定观察 | 需要另行逐句审阅 |
| --- | --- | --- |
| 同名选择及真实新事实 | 同名候选集合、人物 scope、当前 city、另一人物完整行不变 | 选择既有别名不能成为职业或公司；查询条件完整保留 |
| 机构及职位 | 完整 company 精确值、无依据 title 缺席、显式 title 精确值、无待确认项 | 机构与岗位边界是否忠实于原句，保守规则是否吞掉真实职位 |
| 换人与旧消息重试 | 原 user_message_id、原人物 scope、无新增用户消息、域表无变更、各人城市仍正确 | 旧任务说明是否误指当前人物，多人查询是否混写 |
| 聊天邮件及改稿 | 真实 run_turn 产出、域表未写、实际读取相关记忆 | 草稿是否实际可编辑、长度/句数和语气是否满足、待补输入与沟通次序是否完整 |
| 沟通准备起草 | 真实 HTTP 提交与 durable task 完成、ready 草稿、来源 ID 在准备快照内、无联系或承诺写入 | 附件/材料是否虚称完成，发送前步骤是否可操作 |

## 实际执行与审计

`eval/write_quality_v014.py` 复用 `memory_questions.py` 的应用路由、种子数据、实际域表差异、来源核对和保存字段检查。每个场景进入独立进程和临时 SQLite，关闭 embedding；读取项目 `.env` 中的实际模型配置，模型名称写入报告，密钥不写入报告。不会打开用户工作数据库，也不启动 Web 服务。

普通聊天完整执行生产 `harness.run_turn`，不替换分类、抽取、应用、回答或审阅阶段。旧消息重试调用生产持久任务使用的 `run_turn(..., user_message_id=原消息)` 路径，不伪造传输失败、不另造用户消息，也不把当前人物 ID 偷传给原任务。沟通准备走真实 `POST /api/persons/{id}/followups` 和持久任务，仅将调度改为同步执行以取得确定的任务结束状态。

报告保留各步骤输入、原结果、当前/历史人物字段、记忆、待确认项、证据、实际域表差异及本场景消息轨迹。`LLM.chat` 使用只读包装，原方法每次只调用一次，记录适配层返回对象、内容 hash 和耗时，不替换模型结果、不做额外模型重试。生产 `chat_stream` 的聚合草稿保留在回答审阅原稿中；此包装不记录逐个流式 chunk、provider HTTP 原始字节或底层传输重试的每一次尝试，因此审计 call 数不能当全部网络请求数。

字段检查必须读取实际当前行；正确值只在 pending、回执或助手口头声明中出现仍然失败。人物未变化检查比较完整行，能够捕获行数不变但值被覆盖的情况。重试检查比较真实域表；查询审计 evidence 的存在不被误算为记忆写入。普通步骤异常保留异常与已经发生的写入，不把未执行的检查记为通过。若 worker 超时或崩溃，尚未返回的局部审计与临时库无法保留；顶层为计划步骤记录缺失错误，不表示每一步均实际执行。没有自动批准、替换模型提案，或把预期文本当生产抽取结果写回数据库。

自动字段断言证明的是当前值正确，本身不证明该值在本轮新增或只写一次；需结合实际差分与 `applied_patch` 观察。`write_person_scope` 自动覆盖人物、别名、字段、记忆和互动人物表，指定人物未变化比较覆盖人物、别名、字段、记忆四类；承诺、账目、提醒、关系等表虽保留在差分中，逐人物归属需另行审阅。沟通准备会正常创建 followup 和 task，所称「未写入记忆」不表示整个 SQLite 零写入。

首次采样明确暴露的问题：

1. 「顺便替我存一下，她已搬到贵阳了」被正确分类为 mixed，但抽取返回空 people，后续真实工具因记事前缀不在受控代词范围被拒绝。贵阳既没保存也没进 pending，回执没有假称成功。
2. 「帮我起封邮件」「改成两句话」漏获展示许可；前者原模型虽起草，最终只展示资料，后者最终没有改稿。已识别的另一封邮件又因审阅模型把完整正文标为 advice，被 `requested_draft_missing` 拒绝。严格拒绝避免把建议当完成，但这些终稿仍是任务失败。
3. 文本编辑没有自动承接人物范围；首轮两组各有一项 scope 检查失败。原聚合稿也存在询价顺序、缺输入和残句问题，不能只修展示入口就称草稿语义通过。
4. 一条带完整别名的重复城市事实被别名修饰词规则保守跳过，城市字段仍保存。该样本没有出现错误职业候选，不能用它声称已实际观察到职业推断被拦截；后者的依据是控制测试。

首次报告按原样保留，之后补修与回归使用新的实现 hash，不能覆盖或筛掉上述失败。

## 首次失败后的定向补修

已补有限的「顺便＋帮我／替我＋记下／记一下／存下／存一下」记事前缀，仍要求开头锚定与紧接的单人代词。控制测试同时经过真实工具入口、完整 harness 的空抽取后补存路径，以及新命名说话者、条件、否定和复数负控。这是工具纠正路径的人物定位补修，不表示抽取模型的空结果问题已获语义保证。

候选事实中的完整称呼先去除身份片段，再判断是否把修饰词当成新增谓词。真实「乐团周汐喜欢周末徒步」可以保存；仅凭称呼生成的「周汐在乐团工作」仍跳过。该检查仍是词面约束，不能验证所有职业改写。

草稿补修包括前述口语命令与闭合编辑承接，并补上含代词的新稿沿旧承接路径绕过检查的边界；普通代词查询与新的起草请求保留既有行为。资料编辑提示增加段落结构例：正文必须是 draft，发送前步骤放 advice。校验器仍拒绝缺少正文的代笔结果，没有把任意 advice 自动当成草稿。

定向回归输入为 `eval/fixtures/write_quality_v014_regression.json`：保留首次失败的三场景原有全部 6 步、种子与原预期，只改为已知回归 cohort 并记录派生信息；不修改原 fixture。规范化 SHA256 为 `1c1f131e34916580733b2038406b201478c17057c82b29a85902441f82154560`，文件 SHA256 为 `6cc86df51c6e294aabeebbe14a1364a6fc88010296f4775a1ec16995c016c991`。它用于验证开发修复，不能充当新的未见评测。

## 尚存问题
