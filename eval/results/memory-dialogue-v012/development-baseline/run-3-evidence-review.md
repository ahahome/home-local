## 确定性集合比较的实现评审建议（只读）

推荐接在 `harness.run_turn` 完成 focus 与整组注册之后、确定性日期回答之后。触发前同时要求：本轮 selected；至少两条同归属记忆；registration 完整且未超预算；实际 intent 为 query、allow_writes=False；整句是受支持的纯比较请求。不能只凭出现“这些记录”“对照”“区别”就接管，尤其不能吞掉起草邮件/短信、联系方式建议、混合记事或任何追加写入子句。

输出可逐条给当前保存文字和明确日期角色，并按 entity_id + owner 与 binding.reference_snapshots 对齐，报告“相对于上一条回答所保存的快照，记录文字已变化/未变化”。这里只比较字符串，不表示当事人偏好、心理或场景规则已变化；也不能根据日期先后判定取代或互补关系。若记录过长，必须标明截断，不能把截断文本冒充完整原文。

旧锚点不要注册为本轮现行来源：它在编辑后已是旧快照，最终 save_answer 守卫拒绝它是正确行为。可以只说字面是否变化而不重复旧文字，避免把旧引文错误挂到当前来源按钮。跨人物、撤销或转移仍先澄清；确定性分支照常经过 registry.save_answer，不能绕过生成期间变更守卫。
